Flux d'une page XUI

mount_xui_page(s) déclare la route → _resolve_user (même résolveur que get_current_user) → UIContext(plugin_ctx, request, user) → la vue → engine.render(template, ctx), en injectant nav/user/request automatiquement.

Composants <ui.x>

Le moteur (microframe/engine/components/ui_kit.py) fournit {% raw %}{% uivars %}{% endraw %} (props déclarées + attrs pass-through automatique) et les named slots (<ui-slot name="x">) — entièrement gérés par un préprocesseur HTML-sugar, pas de plomberie runtime fragile.

Navigation sans rechargement (xui-boost.js)

Intercepte les clics sur les liens internes, fetch() la même route réelle, extrait #xui-main de la réponse et le remplace — sidebar/header ne bougent pas, l'URL suit les redirections. Dégradation gracieuse totale sans JS.

Thème (xui.theme)

mount_theme(app, engine, css_path) sert un CSS déjà compilé et l'expose comme global Jinja2 (xui_theme_url) — un composant n'a jamais accès au contexte de la page qui l'inclut. Le pipeline Tailwind réel (make css/make theme) utilise le CLI standalone officiel, aucun Node/npm requis.

Sécurité

CSRF (xui.csrf.CSRFMiddleware) sur les chemins cookie-authentifiés mutatifs uniquement. CSP (xui.security) évite le 'unsafe-inline' générique : un hash précis pour l'unique script inline du kit, 'unsafe-eval' documenté (requis par Alpine.js), style-src scindé élément/attribut.

Détail module par module, diagrammes de séquence : docs/architecture.md dans le repo.
