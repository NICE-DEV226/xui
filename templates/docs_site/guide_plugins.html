Pages (mode xui)

Déclarer via xui.urls.path + mount_xui_pages plutôt que des appels mount_xui_page répétés — voir Démarrage.

Mutation = route POST explicite

Jamais de dispatcher (<action>/<remote> interdit, §15). xui.forms.parse_form valide via Pydantic et ré-affiche les erreurs par champ. Le CSRF passe par <ui.form>, jamais un champ caché écrit à la main.

RBAC unifié

ctx.require_role("role") côté page, Depends(RBACChecker(["role"])) côté API pure — même AuthPayload, résolu par la même fonction (_resolve_user). Aucune réimplémentation.

Navigation cross-plugin

nav_registry.register(NavNode(...)) dans on_load(), unregister_plugin() dans on_unload(). L'arbre filtré par rôles est injecté automatiquement dans le contexte — pas de recalcul dans la vue.

Packages UI cross-plugin

Un plugin exporteur (plugins/ui_kit, un vrai exemple du repo) enregistre ses exports à on_load() ; le consommateur déclare requires: [exportateur] dans son plugin.yaml — le kernel garantit l'ordre de chargement, vérifié en pratique (chargement par vagues).

Mode SPA — zéro dépendance xui

Un plugin React/Vue/Svelte n'importe jamais xui (§14) : mount_spa_or_proxy(router, dist_dir=..., dev_server=...) suffit, routes API déclarées avant le fallback.

Détail complet, exemples de code intégraux : docs/plugins.md dans le repo.
